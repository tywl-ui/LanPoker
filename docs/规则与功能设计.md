# 局域网棋牌「斗地主 + 炸金花」—— 规则与功能设计文档

版本：v0.1（2026-08）
状态：评审中

---

## 1. 项目定位

- 平台：Android（Kotlin + Jetpack Compose 原生）
- 定位：朋友聚会用的**可自定义规则**棋牌工具，支持单机同屏/AI 凑桌、局域网联机
- 核心卖点：
  1. 自由设置：几副牌、几人、有没有王、几张王
  2. 炸金花「自填倍数 + 自动记账」，谁也不用掏手机算账
  3. 局域网联机，无服务器、无账号、开热点就能玩
- 商业模式：无（工具型项目）

## 2. 公共配置系统（所有玩法共享）

| 配置项 | 可选范围 | 默认值 | 说明 |
|---|---|---|---|
| 游戏 | 炸金花 / 斗地主 | 炸金花 | |
| 牌副数 | 1 / 2 / 3 副 | 炸金花 1 副、斗地主 1 副 | 总牌数 = 52×副数 + 王数 |
| 人数 | 2 - 8 人 | 炸金花 4 人、斗地主 3 人 | 斗地主上限 6 人（见 §4） |
| 王数量 | 0 - 4 张（可选大小王） | 炸金花 0 张、斗地主 2 张 | 各玩法对王的定义不同，见 §3、§4 |
| 底分单位 | 1 底 = 1 分 / 1 元 / 自定义 | 1 分 | 记账换算基准 |
| 玩家昵称 | 文本 | 座位号 | 局内显示 + 账目显示 |

约束校验：
- 总牌数必须 ≥ 人数 × 3（炸金花）或能完成发牌（斗地主），否则配置非法，界面提示
- 王最多 4 张（即两副牌的最大王数，3 副时可选 6 张——放宽为「0/2/4/6」）

## 3. 炸金花（Zha Jin Hua）

### 3.1 规则概述

每人发 3 张牌，比牌型大小，最大的赢。无出牌顺序、无弃牌流程（模式 A 简化版），或可选完整加注流程（模式 B，后期）。

### 3.2 牌型大小（从小到大）

| 牌型 | 说明 | 大小规则 |
|---|---|---|
| 单张 | 散牌 | 比最大单张 → 次大 → 最小 |
| 对子 | 一对 + 一散 | 比对子点数 → 比散牌 |
| 顺子 | 点数连续（异花） | A23 < 234 < ... < QKA，QKA 最大 |
| 金花 | 同花非顺 | 按单张大小规则 |
| 顺金 | 同花 + 顺子 | 同顺子规则 |
| 豹子 | 三张同点 | AAA > KKK > ... > 222 |

特殊规则（做成开关）：
- **235 吃豹子**：默认开。单张 2、3、5（异花）大于豹子、小于其他所有牌型。多副牌时豹子变多，建议可关。

### 3.3 王的定义

- 王数 = 0：标准玩法
- 王数 > 0：王为**百搭牌**，可代替任意一张牌参与牌型
  - 王 + 对 A = 豹子 A
  - 王 + A K 同花 = 顺金
  - 多个王：全部视为百搭，系统自动选择能组成最大牌型的补法
  - 规则开关：王是否可以参与顺子（默认可以）；「三王 = 最大豹子」特殊定义（默认：按百搭计算）

### 3.4 多副牌的处理

- 两副牌 = 2×52 = 104 张 + 王，支持 2-8 人
- 出现**两手牌完全一样**（点数花色全同，如两副牌各一张 A♠A♣A♥）时，按「平局规则」处理（见 §3.6）
- 多副牌允许两人都拿豹子，按点数比大小（A 豹 > K 豹）

### 3.5 模式 A：自填倍数记账（核心功能，P0）

流程（每局）：
1. 发牌：每人 3 张
2. **传手机看牌**：单机多人时，手机轮流传到每人手里，点一下亮自己的牌，再点确认传给下一个人（其他人无法偷看）
3. 全部确认后，系统自动判定并亮出最大牌型的赢家
4. **输家各自填倍数**：快捷按钮 1× / 2× / 3× / 5× / 10× / 20× + 自定义输入（填自己的底分倍数，即"这局我输几个底"）
5. 系统自动记账：赢家收入 = Σ 每个输家填的 底分×倍数；每个输家扣除自己的
6. 界面显示本局账目 + 总分变动，点「下一局」继续

规则细节：
- 倍数为 0 允许（表示这一家"退钱不输"）
- 输家自己填，填完不可修改，全部填完才结算
- 赢家也可以被填 0（大家商量着退钱），系统如实记录
- 平局（按平局规则）→ 所有玩家本局分数不变（各自填 0 跳过），或按开关「比花色分胜负」

### 3.6 平局规则（开关，默认：和局重发）

| 选项 | 说明 |
|---|---|
| 和局重发 | 牌型完全相同时本局作废重发 |
| 比花色 | 黑桃 > 红桃 > 梅花 > 方块，比最大那张的花色 |
| 平局退钱 | 双方各赢各的（即平局玩家之间不算账） |

### 3.7 模式 B：完整下注流程（P1，后期）

- 轮流行动：闷牌（不看牌）跟注/加注（金额为底分的 2 倍档）、看牌后跟注、弃牌、比牌（指定对手比大小，输者出局）
- 只剩一人或比牌定出胜负，赢者收底池
- 与模式 A 二选一，房间创建时选定
- 实现复杂度高，放后期

## 4. 斗地主（Dou Dizhu）

### 4.1 标准规则（3 人 1 副）

- 54 张（含大小王 2 张），每人 17 张，底牌 3 张
- 叫地主：轮流叫 1/2/3 分，叫的最高者当地主；都不叫则重发
- 地主收 3 张底牌（共 20 张），先出完牌者获胜
- 地主赢则两个农民各输；农民任一先出完则农民方赢

### 4.2 自定义规则扩展（N 人 M 副）

- 总牌数 = 54 × 副数（含 2×副数 张王）
- 发牌：每人均张 = ⌊(总牌数 − 底牌数) / 人数⌋，余数并入底牌
  - 例：4 人 2 副 = 108 张，均张 26，底牌 4
  - 例：5 人 2 副 = 108 张，均张 20，底牌 8
  - 3 人 1 副 = 54 张，均张 17，底牌 3（与标准一致）
- 底牌数默认 3，可由系统自动按上式推算；玩家也可手动指定底牌数（必须 ≤ 2×人数 且满足上式）
- 上限：最多 6 人（再多人单局太长）
- 地主身份：开关「叫地主流程 / 随机地主」
  - 叫地主流程：轮流叫 1/2/3 分，最高者赢，都不叫重发
  - 随机地主：系统随机指定一人，底牌直接并入

### 4.3 牌型（多副扩展版）

| 牌型 | 要求 |
|---|---|
| 单张 / 对子 / 三张 | 点数相同 1/2/3 张 |
| 三带一 / 三带二 | 三张 + 单张 / 三张 + 对子 |
| 顺子 | ≥5 张点数连续（不含 2、王；A 可作低或高，QKA 最大） |
| 连对 | ≥3 对点数连续 |
| 飞机 | ≥2 组三张连续，可带等组数单张或对子 |
| 四带二 | 四张 + 两个单张或两对（开关：默认开） |
| 炸弹 | **4 张及以上**同点数（多副牌扩展：5 张、6 张……），张数多的炸弹大，同张数比点数 |
| 王炸 | **全部王**（1 副 = 双王；2 副 = 四王；可配置为只要 ≥2 王即王炸） |

大小顺序：非炸弹牌型之间按标准规则（点数 → 张数 → 结构）；炸弹压一切非炸弹；王炸压一切炸弹。

多副牌注意点：
- 2 副牌里 2 2 2 2 既是炸弹（四张 2）也可能是连对的一部分，由玩家出牌方式决定，系统只校验合法性
- 带牌（三带一、飞机带牌）不能带炸弹和王炸

### 4.4 翻倍与记分（系统自动计算）

- 基础分 = 地主叫的分（随机地主 = 1）
- 翻倍：每打出一个炸弹 ×2，王炸 ×2（打出才翻，手里有不算）
- 春天：地主一次都没让对方出过牌 → ×2；反春同理
- 地主赢：每个农民各输 基础 × 翻倍；地主输：每个农民各赢
- 4 人以上时农民为多人，各自独立结算（不必"一家输全家输"）
- 开关：「手动倍数」——关 = 纯自动；开 = 自动算完后允许手动改一次，账目以手动为准

## 5. 记账系统（核心功能）

- 一局 = 一个会话（Session），会话内每人一个总分
- 每局结束自动写入账目流水：局号、时间、玩家、倍数、变动分、说明（如"豹子A 吃 顺金KQJ"）
- 界面：
  - 局内：每个座位旁显示实时总分
  - 本局结算弹窗：列出每人的变动明细
  - 历史：本会话所有局记录，可回看
- 会话结束后显示排名，可**导出账单**（纯文本/图片，方便微信转发）
- 数据持久化：本机 SQLite（Room），多会话历史可查
- 联机模式：账目由房主统一记录，结算后广播给所有人

## 6. 游戏模式

### 6.1 单机多人（传手机模式）★核心特色

- 同一台手机，轮流看自己的牌，看完确认传给下一位
- 适合炸金花（3 张牌容易记）；斗地主手牌多，也可做（逐位传手机亮牌）
- 无需联网、无需 AI，第一版就能玩

### 6.2 单机 + AI 凑桌

- 空座位由 AI 补齐，配置时可指定 AI 人数
- 炸金花 AI：按手牌强度启发式（见 §7）
- 斗地主 AI：简化策略

### 6.3 局域网联机

- 房主建房：选玩法 + 配置 + 座位（可留空位给 AI）
- 自动发现：UDP 广播，同网段自动列出房间；兜底：手动输入 IP 加入
- 通信：TCP 长连接；**房主权威**——发牌、判牌、结算都在房主端计算，客户端只上报动作
- 状态同步：全局状态机（准备 → 发牌 → 行动 → 结算 → 下一局），所有动作走房主广播
- 观战：允许其他人加入只看牌局（房主开关）
- 断线处理：60 秒内重连回座位；超时由 AI 托管该座位
- 同一 WiFi 或手机热点均可

## 7. AI 设计

| 玩法 | 策略 |
|---|---|
| 炸金花 | 按手牌牌型强度分档（豹子/顺金=猛攻，金花/顺子=中跟，对子/单张=看情况），概率判断是否继续（P0 可先做"自动填倍数"占位） |
| 斗地主 | 先做"最小合法出牌"（贪心）；再按角色分：地主残局留大牌、农民配合顶牌；最终目标：接入开源 DouZero 类模型（可选） |

AI 不分阶段完成，P0 可先有"能走完流程"即可。

## 8. 功能清单与优先级

### P0（第一版可玩）
1. 配置界面（游戏/副数/人数/王/底分，含非法配置校验）
2. 炸金花模式 A：发牌 → 传手机看牌 → 判定 → 自填倍数 → 自动记账
3. 记账系统：实时总分、本局明细、会话历史、账单导出
4. 斗地主：3 人标准 + N 人 M 副自定义、叫地主、完整牌型引擎、自动记分
5. 单机同屏（传手机）+ 占位 AI（能自动完成流程）

### P1
6. 炸金花 AI、斗地主 AI 策略加强
7. 局域网联机（UDP 发现 + TCP 通信 + 房主权威结算）
8. 炸金花模式 B（完整加注/比牌流程）

### P2
9. 观战、断线重连、AI 托管
10. 局内文字聊天（简单气泡）
11. 多会话历史统计（胜率、输赢曲线）
12. 皮肤/美术替换（牌面、背景做成可替换资源）

## 10. 技术架构

```
LanPoker/
├── core/                    # 纯 Kotlin 规则引擎（无 Android 依赖，可单测）
│   ├── deck/                # 牌、牌堆、洗牌、发牌（支持多副+王）
│   ├── zjh/                 # 炸金花：牌型判定、百搭计算、平局规则
│   ├── ddz/                 # 斗地主：牌型判定、出牌合法性、叫地主、记分
│   ├── ledger/              # 记账：流水、会话、总分计算、账单导出
│   └── config/              # 公共配置模型 + 校验
├── app/                     # Android 应用
│   ├── ui/                  # Compose：配置页、牌桌页、记账页、房间页
│   ├── net/                 # 局域网：UDP 发现、TCP 连接、协议编解码
│   ├── ai/                  # AI 策略（依赖 core）
│   ├── data/                # Room 持久化、会话仓库
│   └── common/              # 主题、资源、通用组件
```

技术要点：
- Kotlin 2.x + Compose（Material 3），minSdk 26，targetSdk 34+
- core 模块零 Android 依赖，规则全部单元测试覆盖（JUnit）
- 网络用 Java Socket + DatagramSocket + Kotlin 协程，协议自定（JSON 文本协议，方便调试）
- 状态管理：ViewModel + StateFlow；UI 事件单向下行
- 美术：牌面 PNG 放 assets，后期做皮肤目录替换
